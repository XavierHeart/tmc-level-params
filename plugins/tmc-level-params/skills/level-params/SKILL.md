# 关卡难度参数生成

本技能给策划用。策划输入一批"主题 + 档位"，每一条是一关；harness 为每一关生成一组参数。参数先用占位名（建筑1、道具3）生成，然后 agent 为每个主题的每个占位起一个和主题强相关的名字，harness 校验后把名字写进全部输出。

分工：

- **harness**（`scripts/level-params-harness`）负责生成、验算、展示和画图。所有数字都由它算，agent 不估、不改。
- **agent** 负责把策划的输入整理成 harness 的输入、为素材起名、运行各步，并汇报结果。名字是 agent 的判断，harness 只做机械校验（填全、不重复、不是占位名、id 格式）。

难度档位是从竞品数据学出来的：用竞品自己的 Hard/ExHard 标签训练一个难度分，再按难度分把竞品关卡等分成 5 档，第 1 档最简单，第 5 档最难。每一关的参数从落在该档的竞品关卡里抽取，然后**物件总数 T、种类数 U 和叠放套数乘 0.5**（2026-10-22 策划反馈：竞品数量太难；我们的素材在同一画布上占地是竞品的 1.4–1.9 倍）。目标种类数、时长、叠放占比和运动载具不缩减。难度分和经验范围按竞品等效值（T ÷ 0.5、U ÷ 0.5）检查，必须落在该档。**2026-10-23 用户决定**：T 还必须落在本档的 T 范围内（竞品该档 T 的 25%–75%，缩减后：第 1 档 78–105、第 2 档 94–121、第 3 档 104–129、第 4 档 110–140、第 5 档 120–158）；同一批里高档关卡的 T 不少于每个低档关卡的 T，不满足时重抽最少的关卡，重抽后仍不满足就报错。方法和口径见 [references/method.md](references/method.md)。

## 输入

一批"主题 + 档位"，每条一关，按策划给的顺序编号为第 1、2、3……关。

- **档位**必须是 1–5 的整数。策划说"简单/中等/困难"这类词时，不自己换算，请策划给出 1–5 的档位。
- **同一个"主题 + 档位"只能出现一次**：它每次都生成同样的参数，重复没有意义。
- 策划可以在对话里列出，也可以给一个 csv 文件，第一行是表头 `主题,档位`（或 `theme,tier`）。

缺少主题或档位时只问缺的那一项，不猜。

## 流程

`$SKILL_DIR` 是本 SKILL.md 所在目录，`H="$SKILL_DIR/scripts/level-params-harness"`。运行目录缺省用当前工作目录下的 `level-params-<日期时间>/`，例如 `level-params-20261012-1530/`。

1. 建立运行目录，二选一：
   - 对话里列出的：`"$H" init --run <运行目录> --item 月球基地:3 --item 冰雪小镇:5 ...`，按策划给的顺序逐条写；
   - csv 文件：`"$H" init --run <运行目录> --batch <文件路径>`。

   输入有错时它报错并停止，把错误原文告诉策划。
2. 生成：`"$H" generate --run <运行目录>`。逐关生成并验算，写出 `level-params.json`、`.csv`、`.xlsx`。返回 1 表示验算失败，把失败项告诉策划，不说成通过。
3. 起名：
   1. 运行 `"$H" names-template --run <运行目录>`，写出 `names.json`。它列出每个主题的每个占位（slot）、类别，以及这个占位在这一批里的作用（`uses`：每关几个、是不是目标、是叠放底座还是叠在别的物件上、所在关卡有没有运动载具）。策划给了以前这个主题的 names.json 时，加 `--from <路径>`，已有的名字会沿用，同一主题前后批次保持同一套名字。
   2. 在 `names.json` 里为每个 slot 填 `name`（中文名，2–16 个字）和 `id`（英文小写、数字、下划线，字母开头）。起名规则：
      - **和主题强相关**：名字要让人一看就知道属于这个主题，例如"月球基地"的建筑写"环形居住舱""氦三提炼站"，不写"房子""工厂"这类哪个主题都能用的词。
      - **具体、能画出来**：一个名字对应一种外形明确的物件，不写抽象概念或场景（如"科技感""基地全景"）。
      - **类别正确**：建筑是固定在地面上的结构；道具是摆在场景里的物件或设施；载具是能开、能飞或能航行的交通工具；角色是人物或拟人角色。
      - **同类之间要一眼能分开**（2026-10-22策划标准）：主色明显不同即可；主色相同时形状必须明显不同；只差大小不算。名字或说明里写出主色，例如"红顶谷仓""蓝顶水塔"。角色的姿态、服饰、头饰也要各不相同，不要多种角色戴同款帽子。
      - **按作用起名**：目标要一眼能认出；叠放底座要能让上层物件站上去或放上去（如平台、车厢、屋顶）；叠在别的物件上的要比底座小；有运动载具的关卡里，载具要是会动的交通工具。
      - 同一主题内名字和 id 都不能重复；不同主题之间可以各自起名。
   3. 运行 `"$H" names-apply --run <运行目录>`。不通过时按它列出的问题改 `names.json`，再运行一次。通过后名字写进 json、csv、xlsx（新增"素材名称" sheet）和 `show` 的输出。

   重新 `generate` 以后，旧名字作废，要重新 `names-template`（没变的占位会保留已写的名字）和 `names-apply`。
4. 画难度图：`"$H" overview --run <运行目录>`，写出 `overview.png`。这张图按真实数据画，不要用生图模型代替。需要 matplotlib；没有安装时把报错里的安装命令告诉策划，其余步骤照常完成。
5. 向策划汇报：
   - 文件路径：`level-params.xlsx`、`level-params.json`、`overview.png`；
   - 每个主题的素材名称（`names-apply` 的输出），以及每关的目标物件叫什么；
   - 一张汇总表，每关一行：序号、主题、档位、难度分、竞品全体排位、物件总数/种类数、目标种类数、叠放、运动载具、时长（取自 `generate` 和 `overview` 的输出）；
   - 验算结果。

策划要求"展示参数""看全部参数"或问某一关时，运行 `"$H" show --run <运行目录>`（某几关加 `--index <序号>`，可重复），**把它的输出原样给策划**，不删减、不改写数字。

其他命令：`check`（复查一份 level-params.json，策划手改过文件后用它）、`status`（当前状态）、`note`（记录决定）、`journal`（查看操作记录）。`init` 可选 `--seed <任意文字>`：同一批输入换一组抽样结果。

## 难度图怎么看

- **上半部分**：横轴是这一批关卡（按输入顺序），纵轴是难度排位——竞品全部关卡中难度分比这一关低的比例，0% 最简单，100% 最难。5 个色带是 5 个档位。红线连起来就是这一批关卡的难度曲线。
- **下半部分**：6 个参数各一张图。每一关画出它所在档的竞品关卡范围（灰色箱体 25%–75%，竖线 10%–90%，横线中位数），红点是这一关的值，能看出这一关在本档里哪一项偏高、哪一项偏低。

## 输出内容

`level-params.json` 的结构：

| 字段 | 含义 |
|---|---|
| `input` | 输入的"主题 + 档位"列表、随机种子 |
| `tier_model` | 难度分模型：特征、权重、分档切点、每档 T 范围（`T_band` 竞品口径，`T_band_scaled` 缩减后）、交叉验证结果 |
| `levels` | 每关一组参数（见下表） |
| `assets` | 每个主题的素材清单：四类各几种、占位名、用到哪些档位 |
| `names` | 每个主题每个占位的名字：`{主题: {占位: {name, id, category}}}`；`names-apply` 之后才有 |
| `checks` | 整体验算 |
| `model_sha256` | 所用竞品统计数据的指纹 |

每关参数：

| 字段 | 含义 |
|---|---|
| `index`、`theme`、`tier`、`score` | 序号、主题、档位、难度分 |
| `form`、`form_description` | 联合形态（竞品关卡聚类出的 F1–F5）和说明 |
| `T`、`U` | 物件总数（含装饰物，3 的倍数）、物件种类数；已按 `count_scale` 缩减 |
| `count_scale` | T、U、叠放套数相对竞品的缩减系数（0.5）；没有这个字段的旧文件按 1 处理 |
| `categories` | 建筑、道具、载具、角色各几种、共几个 |
| `per_kind` | 每种物件的数量（占位名，每种是 3 的倍数） |
| `targets` | 目标：哪几种、每种几个；目标数量等于这种物件在关卡里的全部数量 |
| `stacking` | 是否叠放、几层、哪几种物件叠在一起、各几套 |
| `motion` | 是否有运动载具 |
| `duration_s` | 时长（秒） |
| `basis`、`variation` | 依据：T/U、四类拆分、叠放结构分别取自哪个竞品关卡，以及 T/U 的变化量；`basis.order_redrawn` 表示这一关因批内顺序被重抽 |
| `checks` | 这一关的验算结果 |

xlsx 有四个 sheet：关卡参数（每关一行，起名后显示"名字（占位）"）、素材清单（每个主题一行）、素材名称（每个占位一行）、验算。xlsx 需要 `xlsxwriter`；没有安装时只跳过 xlsx，并提示 `pip install xlsxwriter`。运行目录里还有 `names.json`（起名记录）、`run.json`（输入和指纹）和 `journal.jsonl`（操作记录）。

## 更新竞品数据

竞品数据更新后重新学习一次，生成新的 `model.json`（包括难度档位）：

```bash
python3 "$SKILL_DIR/scripts/learn.py" --data "<tmc资源包/数据>"
```

`model.json` 变了以后，同一输入的结果也会变。`run.json` 和参数文件里都记录了 `model_sha256`。

## 范围和限制

- 只生成参数和素材名字，不生成图片，不摆放关卡。
- 名字由 agent 判断，harness 不判断名字是否贴合主题；策划对名字不满意时，直接说要改哪几个，agent 改 `names.json` 后重新 `names-apply`。
- 同一个"主题 + 档位"（和种子）总是得到同样的参数；只有批内顺序要求重抽时（`basis.order_redrawn`），结果才和这一批里的其他关有关。
- 难度分学的是竞品怎么标难度，不是玩家实际觉得有多难；摆放密度、遮挡、路径没有进入难度分。
- 难度分落在档内；同一批里 T 逐档不减，其他单项参数不一定逐档升高。
- 物件总数包含装饰物，和规则表的统计一致。
