# 关卡难度参数生成

本技能给策划用。策划输入一批"主题 + 档位"，每一条是一关；harness 为每一关生成一组参数。物件用占位名（建筑1、道具3）；关卡生产时再把占位名换成这个主题的具体物件。

分工：

- **harness**（`scripts/level-params-harness`）负责生成、验算、展示和画图。所有数字都由它算，agent 不估、不改。
- **agent** 负责把策划的输入整理成 harness 的输入、运行各步，并汇报结果。

难度档位是从竞品数据学出来的：用竞品自己的 Hard/ExHard 标签训练一个难度分，再按难度分把竞品关卡等分成 5 档，第 1 档最简单，第 5 档最难。每一关的参数从落在该档的竞品关卡里抽取，生成后再用同一个难度分检查，必须落在该档。方法和口径见 [references/method.md](references/method.md)。

## 输入

一批"主题 + 档位"，每条一关，按策划给的顺序编号为第 1、2、3……关。

- **档位**必须是 1–5 的整数。策划说"简单/中等/困难"这类词时，不自己换算，请策划给出 1–5 的档位。
- **同一个"主题 + 档位"只能出现一次**：它每次都生成同样的参数，重复没有意义。
- 策划可以在对话里列出，也可以给一个 csv 文件，第一行是表头 `主题,档位`（或 `theme,tier`）。

缺少主题或档位时只问缺的那一项，不猜。

## 流程

`$SKILL_DIR` 是本 SKILL.md 所在目录，`H="$SKILL_DIR/scripts/level-params-harness"`。运行目录缺省用当前工作目录下的 `level-params-<日期时间>/`，例如 `level-params-20261012-1530/`。

1. 建立运行目录，二选一：
   - 对话里列出的：`"$H" init --run <运行目录> --item 月球基地:3 --item 冰雪小镇:5 ...`，按策划给的顺序逐条写；
   - csv 文件：`"$H" init --run <运行目录> --batch <文件路径>`。

   输入有错时它报错并停止，把错误原文告诉策划。
2. 生成：`"$H" generate --run <运行目录>`。逐关生成并验算，写出 `level-params.json`、`.csv`、`.xlsx`。返回 1 表示验算失败，把失败项告诉策划，不说成通过。
3. 画难度图：`"$H" overview --run <运行目录>`，写出 `overview.png`。这张图按真实数据画，不要用生图模型代替。需要 matplotlib；没有安装时把报错里的安装命令告诉策划，其余步骤照常完成。
4. 向策划汇报：
   - 文件路径：`level-params.xlsx`、`level-params.json`、`overview.png`；
   - 一张汇总表，每关一行：序号、主题、档位、难度分、竞品全体排位、物件总数/种类数、目标种类数、叠放、运动载具、时长（取自 `generate` 和 `overview` 的输出）；
   - 验算结果。

策划要求"展示参数""看全部参数"或问某一关时，运行 `"$H" show --run <运行目录>`（某几关加 `--index <序号>`，可重复），**把它的输出原样给策划**，不删减、不改写数字。

其他命令：`check`（复查一份 level-params.json，策划手改过文件后用它）、`status`（当前状态）、`note`（记录决定）、`journal`（查看操作记录）。`init` 可选 `--seed <任意文字>`：同一批输入换一组抽样结果。

## 难度图怎么看

- **上半部分**：横轴是这一批关卡（按输入顺序），纵轴是难度排位——竞品全部关卡中难度分比这一关低的比例，0% 最简单，100% 最难。5 个色带是 5 个档位。红线连起来就是这一批关卡的难度曲线。
- **下半部分**：6 个参数各一张图。每一关画出它所在档的竞品关卡范围（灰色箱体 25%–75%，竖线 10%–90%，横线中位数），红点是这一关的值，能看出这一关在本档里哪一项偏高、哪一项偏低。

## 输出内容

`level-params.json` 的结构：

| 字段 | 含义 |
|---|---|
| `input` | 输入的"主题 + 档位"列表、随机种子 |
| `tier_model` | 难度分模型：特征、权重、分档切点、交叉验证结果 |
| `levels` | 每关一组参数（见下表） |
| `assets` | 每个主题的素材清单：四类各几种、占位名、用到哪些档位 |
| `checks` | 整体验算 |
| `model_sha256` | 所用竞品统计数据的指纹 |

每关参数：

| 字段 | 含义 |
|---|---|
| `index`、`theme`、`tier`、`score` | 序号、主题、档位、难度分 |
| `form`、`form_description` | 联合形态（竞品关卡聚类出的 F1–F5）和说明 |
| `T`、`U` | 物件总数（含装饰物，3 的倍数）、物件种类数 |
| `categories` | 建筑、道具、载具、角色各几种、共几个 |
| `per_kind` | 每种物件的数量（占位名，每种是 3 的倍数） |
| `targets` | 目标：哪几种、每种几个；目标数量等于这种物件在关卡里的全部数量 |
| `stacking` | 是否叠放、几层、哪几种物件叠在一起、各几套 |
| `motion` | 是否有运动载具 |
| `duration_s` | 时长（秒） |
| `basis`、`variation` | 依据：T/U、四类拆分、叠放结构分别取自哪个竞品关卡，以及 T/U 的变化量 |
| `checks` | 这一关的验算结果 |

xlsx 有三个 sheet：关卡参数（每关一行）、素材清单（每个主题一行）、验算。xlsx 需要 `xlsxwriter`；没有安装时只跳过 xlsx，并提示 `pip install xlsxwriter`。运行目录里还有 `run.json`（输入和指纹）和 `journal.jsonl`（操作记录）。

## 更新竞品数据

竞品数据更新后重新学习一次，生成新的 `model.json`（包括难度档位）：

```bash
python3 "$SKILL_DIR/scripts/learn.py" --data "<tmc资源包/数据>"
```

`model.json` 变了以后，同一输入的结果也会变。`run.json` 和参数文件里都记录了 `model_sha256`。

## 范围和限制

- 只生成参数，不生成图片，不摆放关卡。
- 同一个"主题 + 档位"（和种子）总是得到同样的参数，和这一批里还有哪些关无关。
- 难度分学的是竞品怎么标难度，不是玩家实际觉得有多难；摆放密度、遮挡、路径没有进入难度分。
- 难度分落在档内，但单项参数不一定逐档升高。
- 物件总数包含装饰物，和规则表的统计一致。
