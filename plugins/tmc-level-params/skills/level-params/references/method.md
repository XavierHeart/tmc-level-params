# 生成方法与口径

本文说明难度档位怎么从竞品数据学出来、每一关的参数怎么生成，以及统计口径和限制。

## 难度档位

竞品主线 2998 关自带难度标签：Normal 2399 关、Hard 334 关、ExHard 265 关。这三档在参数上重叠很大，直接按标签分档，Hard 和 ExHard 的参数很难拉开。所以先从标签里学出一个难度分，再按难度分重新切成 5 档。

1. **特征**：每关取 6 个参数，生成的参数也能算出同样的 6 个值。

   | 特征 | 计算 |
   |---|---|
   | 物件总数 | ln(T) |
   | 物件种类数 | U |
   | 目标种类数 | 目标有几种 |
   | 时长 | 秒 |
   | 叠放占比 | 叠在上层的物件数 ÷ T |
   | 有运动载具 | 有为 1，没有为 0 |

   目标总数没有用：竞品里只有约 40% 的目标数量能对上物件，其余要靠估计。

2. **模型**：逻辑回归，预测一关被竞品标成 Hard 或 ExHard 的概率。Normal 和 Hard/ExHard 的关数差很多，训练时按类别加权，两边同样重要。特征先标准化，再加 L2 正则。只用 Python 标准库，结果是确定的。
3. **难度分**：模型输出的对数几率。分越高，越像竞品的 Hard/ExHard。
4. **切档**：按难度分从低到高排序全部 2998 关，在 20%、40%、60%、80% 分位处切开，得到 5 档，每档约 600 关。
5. **检验**：5 折交叉验证。具体数值（AUC、各档的标签构成、特征权重）在 `model.json` 的 `tiers` 里，也写在生成结果的 `tier_model` 里。

## 每一关参数的生成

输入是一批"主题 + 档位"，每条一关。一关的样本池是落在它所在档的竞品关卡（约 600 关）。

| 步骤 | 做法 |
|---|---|
| 联合形态 | 按这一档里可完整分类关卡的形态分布抽样 |
| T/U | 从池中取一对真实 T/U；T 变化 ±0/3/6 后取 3 的倍数，U 变化 ±0/1；然后两者乘 `COUNT_SCALE`（0.5），T 取 3 的倍数，U 四舍五入 |
| 四类拆分 | 取一个同形态（优先同档）的真实样本，按它的种类比例和数量比例整体拆分 |
| 目标 | 种类数和单个目标数量从池中取；目标种类的数量 = 该种类全部数量 |
| 叠放 | 按池的叠放率开关；取池中一个真实关卡的叠放结构，套数乘 0.5 后四舍五入到 3 的倍数 |
| 运动载具 | 按池的运动率开关；开启时只用含载具的拆分样本 |
| 时长 | 从池中取 |
| 难度分 | 用同一个模型给生成的参数打分，T、U 先换回竞品等效值（÷ 0.5），必须落在该档的分数区间内 |
| T 在档内范围 | T（缩减后）必须在该档的 T 范围内，见下文"每档 T 范围" |
| 验算 | 种类/数量加总、3 倍数、U≤T/3、目标明细、叠放套数与容量、运动前提、难度分在档内、T 在档内范围、经验范围。不通过就重抽这一关（最多 200 次） |

**同一主题的各关用同一套占位名**。每类都从 1 开始编号，例如某关有 5 种建筑，就用建筑1–建筑5。每个主题的素材清单取这一批里该主题各关每类的最大种类数，美术按清单画一次，这些关都够用。

**主题名只用作随机种子**，不影响参数的统计来源。同一个"主题 + 档位"（和可选种子）总是得到完全相同的参数；只有批内顺序规则（见下文）要求重抽时，结果才和同一批里的其他关有关。不同档位的参数不可能完全相同，因为参数相同则难度分相同，只能落在同一档。

整体验算：每关验算通过、没有重复的输入、序号连续、每关的物件都在本主题的素材清单内。

## 数量缩减（2026-10-22）

策划反馈：参数完全照竞品会过难，简单档也一样，要求整体下调 40%–50%，同时减少因物件太多而统一缩小的情况。依据：竞品每关画布同样是 40.96 × 40.96；把竞品 6 个真实关卡的物件换成我们素材的实测尺寸（lp-01、lp-08、lp-09），同样的物件清单占地是竞品的 1.4–1.9 倍。要和竞品一样挤，T 要乘 0.52–0.72；取 0.5 时所有测过的情况都不比竞品挤。T 和 U 同时减半，每种物件的个数和竞品相同，3 消结构不变。目标种类数不减半（竞品中位数 3，减半只剩 1–2 种），时长不缩短（缩短会更难）。

各档中位数（竞品 → 生成）：T 181→90、216→108、230→115、247→124、268→134；U 21→10、25.5→13、30→15、35→18、47→24。尺寸只测了 3 个我们的关卡和 6 个竞品关卡，面积按包围框计算。

## 每档 T 范围和批内顺序（2026-10-23 用户决定）

策划反馈：第 3 档出现 T = 96 的关卡，比同批第 2 档的关卡物件还少。原因是 T 只是难度分的 6 个特征之一，难度分在档内时 T 仍可能偏低或偏高。

1. **每档 T 范围**：用同一个难度分模型给全部竞品关卡分档，取每档真实 T 的 25%–75% 分位（含端点插值），乘 `COUNT_SCALE` 后四舍五入。结果是：第 1 档 78–105、第 2 档 94–121、第 3 档 104–129、第 4 档 110–140、第 5 档 120–158。生成的 T 不在本档范围内就重抽。范围由 `learn.py` 写进 `model.json` 的 `tiers.T_band`（竞品口径），生成结果的 `tier_model` 里有 `T_band` 和缩减后的 `T_band_scaled`。
2. **批内顺序**：同一批里，高档关卡的 T 必须不少于每一个低档关卡的 T。各关先按自己的种子抽；不满足时，在每关自己的 200 次种子抽样里重选，改动的关卡数最少，被改的关取范围内最早的一次，记 `basis.order_redrawn`。结果是确定的。重选后仍不满足就报错停止。

两项检查写在每关的 `checks` 里：`T在档内范围`、`高档不少于低档`。

## 口径与限制

- **T 含装饰物**。T 是一关的全部摆放行，和规则表的统计一致。`nc_`、`robot_` 等装饰物（每关数量通常不是 3 的倍数）也计入 T。生成时 T 全部分到四类里。
- **形态 F1–F5 是重新聚类的结果**，和规则表里的 F1–F5 不一一对应。只有 508 关能完整分类，各档的形态分布来自这些关卡。
- **目标数量**：只有约 40% 的目标名能对上已识别物件；生成时从这一档已知的目标数量中抽取。
- **叠放"层"** = 底座 + 上层物件的件数（2 层 = 1+1，3 层 = 1+2）。数据只记录嵌套顺序，没有区分"竖着叠"和"一个底座上放两个"。物件数量不够放下某个组合时会丢弃它，丢弃数记录在 `basis.stack_dropped`。
- **难度分只看参数**。摆放密度、遮挡、路径要布局后才能测量，没有进入难度分。
- **竞品的标签本身**：难度分学的是"竞品怎么标"，不是玩家实际觉得有多难。
